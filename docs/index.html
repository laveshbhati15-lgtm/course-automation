Standalone & Local Automation CLI

CodeChef Course Automation & Progress Inspector

A lightweight, portable open-source CLI tool for inspecting course progress, reading theory concepts, and assisting with coursework on CodeChef Learn. Runs completely on your local machine using standard Python and Playwright.

Created by Lavesh Bhati
Get Started View on GitHub

What the Project Does

Course Automation is designed to run locally from your terminal, connecting to your authenticated CodeChef Learn session via Playwright without requiring browser extensions or cloud daemons:

1

Inspect Course Structure

Dynamically discovers modules, theory lessons, quizzes, and coding exercises from any valid CodeChef Learn course URL or active browser tab.

2

Read Theory Concepts

Smoothly scrolls through reading lessons to trigger dynamic rendering (MathJax and code snippets) and advances using accessible navigation controls.

3

Assist with Quizzes (MCQs)

Extracts questions and choices, evaluates answers using heuristic matching or the Gemini AI search & reasoning engine, and requires human confirmation before submitting.

4

Assist with Coding Labs

Injects solutions into Monaco and Ace code editors across C++, Java, C, and Python using base64 buffer injection to prevent quotation or newline corruption.

5

Track Offline Progress

Maintains a local SQLite database of course syllabi, module breakdowns, and completion metrics without requiring an active browser connection.

6

Safety by Default

Provides a non-mutating --dry-run mode to simulate operations without submitting, plus regex filters to redact credentials from all logs.

Features & Known Limitations

Core Features

  • Dynamic Course Discovery: Operates on any valid CodeChef Learn course URL; nothing is hardcoded to a specific subject.
  • Active Tab Auto-Detection: Detects which course tab is currently open in your browser session if no URL is passed.
  • Zero-Mutation Dry-Run: Full simulation mode (--dry-run) to inspect pages, read content, and reason about questions without clicking submit or altering course progress.
  • Interactive Confirmation: Prompts for terminal approval before any live submission unless --auto-approve is explicitly passed.
  • Credential Redaction: Automatically scrubs API keys, session tokens, and passwords from console output and log files.

Known Limitations

Scope & Platform Limitations

Locked Activities (LOCKED_SKIPPED): Activities locked by prerequisite gates or scheduling deadlines are recognized honestly and skipped; they are never bypassed.

Proctored Exams: Proctored tests, webcam-monitored exams, or lockdown browser assessments are completely unsupported.

CAPTCHAs / Bot Challenges: Rare Cloudflare or CAPTCHA challenges require manual completion in the headful browser window.

Supported Sites: Only CodeChef Learn is currently implemented.

Download Project

Run course-automation config --check-ai to confirm live Gemini API connection and model readiness.

Fedora Linux Complete Installation Guide

Fedora 39 / 40 / 41 / 42

This guide is written specifically for beginners who may be new to the Linux terminal. Follow each step sequentially to set up your environment, install dependencies using Fedora's DNF package manager, and launch the tool.

Beginner Terminal Tip

Commands shown in dark boxes below are meant to be entered into your Terminal application. You can paste into most Linux terminals using Ctrl + Shift + V or right-clicking and selecting Paste.

Step 1: Prerequisites & System Verification

First, open your terminal. In GNOME (default Fedora desktop), press the Super (Windows) key, type Terminal, and press Enter (or use shortcut Ctrl + Alt + T).

Verify your Fedora version and system information:

bash
cat /etc/os-release

Check your installed Python version. The project strictly requires Python >= 3.10 (Python 3.12 is recommended and ships standard with Fedora 39/40):

bash
python3 --version

Check if Git is installed:

bash
git --version

Step 2: Install Required System Packages via DNF

Fedora uses the dnf package manager. The sudo command executes the operation with administrative privileges; you will be prompted for your user password (characters will not show on screen as you type, which is normal).

bash
sudo dnf install -y git python3 python3-pip python3-devel
  • git: Downloads and tracks the project from GitHub.
  • python3: The Python 3 programming language runtime.
  • python3-pip: Python package manager for installing project dependencies.
  • python3-devel: C header files and libraries needed to build native extensions.

Step 3: Download the Project (Clone Repository)

"Cloning" creates an identical, full copy of the project repository on your machine. Run:

bash
git clone https://github.com/laveshbhati15-lgtm/course-automation.git
cd course-automation

Confirm that you are inside the project directory by checking your current folder and listing its contents:

bash
pwd
ls

You should see files such as pyproject.toml, README.md, src, and docs.

Step 4: Create & Activate a Python Virtual Environment

In modern Linux distributions (including Fedora), Python packages should always be installed inside a virtual environment rather than globally. This prevents conflicts with system packages and avoids externally-managed-environment errors:

bash
python3 -m venv .venv
source .venv/bin/activate

How to verify activation: Your terminal prompt will now start with (.venv), indicating that all subsequent Python and pip commands will run in this isolated environment.

Step 5: Upgrade Pip & Install Dependencies (including AI Search Engine)

With (.venv) active, upgrade pip and install the package with AI search extras enabled:

bash
python3 -m pip install --upgrade pip
pip install -e ".[ai]"

Note: Installing .[ai] installs google-genai, the client library powering the Gemini search and reasoning engine.

Step 6: Configure the Gemini API (Required for Search Engine)

Mandatory Step for Search & Deduction Features

Configuring the Gemini API is a mandatory installation step if you plan to use the AI-powered search and deduction engine (answering quizzes, MCQs, and coding challenges). While non-API commands like auth, inspect, and status work without a key, the search engine requires a valid personal Gemini key.

Follow these steps to configure your environment securely on Fedora:

  1. Obtain a personal API key from Google AI Studio.
  2. Copy the repository template to create your local .env file:
    bash
    cp .env.example .env
  3. Edit .env using your favorite text editor (e.g. nano .env or gedit .env):
    env
    # AI Search Engine Configuration (Required for MCQs and Code Reasoning)
AI_PROVIDER=gemini
GEMINI_API_KEY=your_gemini_api_key_here
GEMINI_MODEL=gemini-flash-lite-latest
  4. Configuration Details:
    • AI_PROVIDER=gemini: The project defaults to none. You must explicitly specify gemini to activate the AI search engine.
    • GEMINI_API_KEY: Your secret API key from Google AI Studio. Never share or commit this key.
    • GEMINI_MODEL: Defaults to gemini-flash-lite-latest.
Security & Git Tracking Confirmation

The project configuration engine (Pydantic Settings) automatically loads .env on startup. The .env file is strictly excluded from Git tracking via .gitignore (line 70), ensuring your secret key is never accidentally committed or pushed.

Step 7: Install Browser Dependencies (Playwright & DNF Libraries)

Install Playwright's Chromium browser binary:

bash
playwright install chromium

On Linux, Chromium requires system shared libraries (such as graphics, font, and audio packages). Install the required system dependencies:

bash
playwright install-deps chromium

(Playwright will ask for your sudo password to install any missing DNF packages automatically. If you prefer to install them manually, run: sudo dnf install -y alsa-lib at-spi2-atk cairo cups-libs dbus-libs expat glib2 gtk3 libX11 libXcomposite libXdamage libXext libXfixes libXrandr libdrm libgbm libxcb libxshmfence mesa-libgbm nss nspr pango.)

Step 8: Authenticate with CodeChef

Authenticate once using the headful browser to create your persistent session:

bash
course-automation auth --timeout 300
  1. A visible Chromium browser window will open to https://www.codechef.com/login.
  2. You must manually log in inside this browser window using your CodeChef username/password, Google OAuth, or GitHub.
  3. The CLI polls your open browser tabs for authenticated course indicators and session cookies.
  4. Once detected, the terminal prints [SUCCESS] Authentication detected! Session saved to profile. and closes the browser cleanly.
Troubleshooting Browser Login on Fedora

If you sign in successfully in the browser but the CLI continues waiting and eventually times out:

  • OAuth Multi-tab: Google or GitHub OAuth may open your authenticated session in a new tab. Keep the browser open and make sure you navigate to your course URL (e.g. https://www.codechef.com/learn/course/<slug>) so the detector can identify course elements.
  • Do Not Close Manually: Allow the CLI to detect the session and exit automatically.
  • Extend Timeout: If your login takes longer, run: course-automation auth --timeout 600.
  • Diagnostic Logs: Collect sanitized logs without exposing credentials: LOG_LEVEL=DEBUG course-automation auth --timeout 300.

Step 9: Verify Your Search Engine Setup

Do not assume the search engine is configured simply because the CLI launches. Run this dedicated, non-destructive health check to verify your Gemini API key and model connectivity:

bash
course-automation config --check-ai

Expected Output:

terminal
[AI Check] Testing Gemini API connection...
[AI Check] Gemini search & reasoning engine connected successfully!
  Model: gemini-flash-lite-latest
  Ping response: pong

You can also check resolved local configuration paths and settings:

bash
course-automation config
Understanding API Limits & Common Errors
  • API Limits & Quotas: Free and pay-as-you-go tiers in Google AI Studio have per-minute and per-day rate limits. Usage is not unlimited.
  • Missing API Key: If GEMINI_API_KEY is unset or empty, running solve on MCQs will stop with: RuntimeError: GEMINI_API_KEY is not set.
  • Invalid Key (400 / 403): If the key is corrupted or revoked, the check outputs Gemini ping failed: API_KEY_INVALID. Double-check your key in .env.
  • Quota Exhaustion (429): If you encounter ResourceExhausted / 429, wait a minute for your quota window to reset or upgrade your tier in Google AI Studio.

Step 10: Common Fedora Troubleshooting

Cause: You are running an older Fedora release (e.g. Fedora 38 or older) with Python 3.9.

Solution: Install Python 3.12 explicitly and recreate your environment:

bash
sudo dnf install -y python3.12 python3.12-devel
rm -rf .venv
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .

Cause: Running pip install directly against Fedora's system Python without activating .venv.

Solution: Always activate your virtual environment first: source .venv/bin/activate. The prompt will show (.venv).

Symptom: fatal: unable to access 'https://github.com/...': Could not resolve host.

Solution: Verify your internet connection with ping -c 3 fedoraproject.org. If you are behind a university or corporate proxy, configure Git proxy settings or download the source code ZIP archive directly.

Symptom: Host system is missing dependencies to run browsers.

Solution: Run playwright install-deps chromium to install missing RPM libraries. On Wayland desktops, ensure XWayland compatibility is installed: sudo dnf install -y xorg-x11-server-Xwayland.

Symptom: sqlite3.OperationalError: unable to open database file.

Solution: Restore ownership of your user data directory: sudo chown -R $USER:$USER ~/.course_automation.

Symptom: ModuleNotFoundError: No module named 'pytest' when running tests.

Solution: Install the development dependencies inside your activated virtual environment: pip install -e ".[dev]" and run pytest -v.

Authentication & Browser Session Handling

Course Automation uses an isolated persistent browser profile to maintain your logged-in state across CLI runs without storing your plaintext username or password.

Interactive Manual Login Command

To authenticate, launch a visible (headful) browser window from your terminal:

bash 
course-automation auth

By default, the CLI waits up to 300 seconds for you to complete login. If you need more time (for two-factor authentication or slower connections), pass the --timeout option:

bash 
course-automation auth --timeout 600
Supported CLI Options for auth

The auth command supports the following options:

  • --timeout <int>: Maximum wait time in seconds for manual login (default: 300).
  • --site <str>: Target learning platform (default: codechef).
  • --help: Display command usage information.

Note: Unsupported flags such as --manual do not exist. Authentication is always interactive and headful.

How the Authentication Workflow Works

  1. Browser Launch: A visible (headful) Chromium window opens automatically to the CodeChef login page.
  2. Manual Login: You must manually enter your credentials or sign in using your preferred identity provider (CodeChef username/password, Google OAuth, or GitHub) directly in the opened browser window. The CLI does not read, intercept, or enter your credentials.
  3. Session Detection: As you sign in, the CLI monitors open browser tabs for authenticated course indicators (such as user avatar elements, course syllabus cards, and session cookies).
  4. Profile Persistence: Once authenticated state is verified, the CLI prints [SUCCESS] Authentication detected! Session saved to profile. and disconnects the browser cleanly, persisting your session.
Session Storage Security Notice (No Application Encryption)

Browser cookies and session state are saved locally inside ~/.course_automation/browser_profile (or %USERPROFILE%\.course_automation\browser_profile on Windows) in standard Chromium directory format.

They are NOT encrypted at rest by the application. Session privacy is protected strictly by your operating system user account filesystem permissions. Never share or commit your .course_automation folder to version control.

Configuration & Gemini API Setup (Required for Search Engine)

Mandatory Requirement for AI-Powered Search

Configuring a personal Google Gemini API key is a required installation step to access the project's AI-powered search and reasoning engine. Without a valid API key, the search engine cannot evaluate question prompts, search lesson context, or synthesize code solutions.

Feature Breakdown: Required vs. Non-API Features

Feature / CLI Command API Key Required? Behavior Without API Key
AI Search & Question Answering (course-automation solve) Required Skipped; reports INSPECTED_NO_AI on quizzes and coding labs.
Automated Code Generation (course-automation solve --coding-only) Required Inspects problem statements but cannot synthesize code solutions without Gemini.
Interactive One-Time Login (course-automation auth) Not Required Fully functional; saves session cookies in ~/.course_automation/browser_profile.
Syllabus Inspection & Progress (course-automation inspect) Not Required Fully functional; parses curriculum structure and completion percentages offline.
Assisted Theory Reading (course-automation solve --theory-only) Not Required Fully functional; reads lessons, renders LaTeX, and clicks enabled Next buttons.
Offline Local Progress History (course-automation status) Not Required Fully functional; queries cached local SQLite database without network or API calls.
Architecture Note: How the AI Search Engine Operates

The project's AI search engine uses Google Gemini (gemini-flash-lite-latest via the official google-genai SDK) to perform structured conceptual search, semantic deduction, and solution synthesis directly across lesson context, theorem definitions, and question prompts. There is no separate third-party web search provider or external search.answer endpoint.

Step 1: Obtain Your Personal Google Gemini API Key

  1. Visit Google AI Studio (aistudio.google.com/app/apikey).
  2. Sign in with your personal Google account.
  3. Click Create API Key, select or create a project, and copy your generated key.
Personal Responsibility & Quota Limits

Each user must configure their own personal API key. Never share your key with classmates or commit it to GitHub. Google AI Studio provides a free developer tier with rate limits (Requests Per Minute / Requests Per Day). Usage availability and quotas depend entirely on your Google AI Studio account. The project maintainers do not supply, subsidize, or guarantee unlimited API quotas.

Step 2: Create Your Local .env File

Open .env in your text editor. By default, AI_PROVIDER is set to none. You must explicitly set AI_PROVIDER=gemini and supply your API key:

Git Secret Hygiene Verified

Ensure the official google-genai SDK is installed in your active virtual environment:

Step 5: Verify Your Search Engine Setup

Do not assume the API is working merely because the CLI opens. Use these safe, non-destructive commands to confirm that your search engine is configured and operational:

1. Inspect Resolved Configuration:

bash

Expected: AI Provider: gemini, Gemini Model: gemini-flash-lite-latest, and Gemini API Key: [SET (REDACTED)]. If it says [NOT SET], verify that .env exists in the project root.

2. Test Live Gemini API Connection (Health Check):

bash
course-automation config --check-ai

3. Non-Destructive Search Simulation (Dry-Run):

bash
course-automation solve <COURSE_URL> --dry-run

Runs the full AI search engine to analyze question prompts, extract options, and compute answers, but **does not click options or submit answers** on CodeChef servers.

API Limits, Quotas & Error Recognition

  • Missing Key Error (ValueError: GEMINI_API_KEY is not set): Occurs if AI_PROVIDER=gemini but GEMINI_API_KEY is blank. Solution: Add your key to .env.
  • Invalid Key Error (400 API_KEY_INVALID or 403 PERMISSION_DENIED): Occurs if the key was revoked or mistyped. Solution: Generate a fresh key at Google AI Studio.
  • Quota / Rate Limit Error (429 RESOURCE_EXHAUSTED): Occurs if the free tier request limit is reached. Solution: Wait 60 seconds before retrying, or switch to reading lessons via --theory-only.

Safe Dry-Run Testing

The --dry-run flag is an intentional safety feature designed to protect your account and course progress:

Theory Reading Lessons

Scrolls down the page to trigger dynamic MathJax rendering and code formatting, verifies that the Next/Continue button is enabled, but does not click it.

Quizzes (MCQs)

Extracts the question stem and all multiple-choice options, evaluates reasoning, but never clicks any radio button or submits the answer.

Coding Exercises

Detects the problem statement, active language, and starter code without clicking Run or submitting code to the grading queue.

Symptom: You manually log in to CodeChef in the opened browser window and the course or dashboard is visibly displayed, but the terminal continues waiting and eventually reports: Authentication was not completed within the time limit.

Potential Causes:

  • Multi-tab / OAuth redirection: Signing in via Google or GitHub OAuth may open a popup or redirect in a new tab, leaving the initial tab on an intermediate URL while the course loads in another tab.
  • Course page not loaded: The browser remained on an account settings, payment, or home page rather than an active course or learning dashboard.
  • Browser window closed prematurely: Closing the browser before the CLI confirms authentication interrupts session verification.

Recommended Actions:

  1. Keep the browser open: Do not close the Chromium browser manually. The tool will automatically close it and save the session once authentication is verified.
  2. Navigate to your course: If redirected to the home page or a blank tab, navigate directly to your course (e.g. https://www.codechef.com/learn/course/...) so the detector can identify course elements.
  3. Extend the timeout: If your login flow or 2FA requires more time, increase the timeout:
    bash
    course-automation auth --timeout 600

How to Collect Safe Diagnostic Logs:

To inspect what the detector sees during authentication without leaking any secrets, run the command with debug logging enabled:

macOS / Linux
LOG_LEVEL=DEBUG course-automation auth --timeout 300
Windows PowerShell
$env:LOG_LEVEL="DEBUG"; course-automation auth --timeout 300
